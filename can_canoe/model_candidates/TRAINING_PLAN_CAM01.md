# 전방 중앙(CAM01) 학습 계획 — 학습용 PC 에서 시작하기 전 정리

목표(사용자 확정): 한 모델로 **신호등 색 + 객체(사람·자동차) + 원거리 차선**, 칩 지연 ≤ 100 ms, ≥ 5 fps, 인식률 80%.
거리(신호등·객체·**장애물**)는 깊이 노드로 계산하므로 학습 대상이 아니다. 학습 PC: 사용자 확인 — 성능 좋은 산업용 PC(모델·VRAM 미확인), 무기한 사용.

## 0. 학습 PC 에서 가장 먼저 할 일
1. `python3 check_training_pc.py` 결과를 알려 주기 (GPU 모델·VRAM, CUDA, 디스크 여유, RAM, 인터넷).
2. 저장소 받기(`git clone https://github.com/bongpodoal/camera_ai.git`) → 후보 저장소 받기 (`measure_arch.py` 머리말의 명령).
3. BDD100K 받기 (사용자 계정 필요, 이미지 약 5.4~7.1 GB). 이 맥에서는 `bdd-data.berkeley.edu` 에 인증서 오류가 났다(맥의 설정 문제일 수 있음). 막히면 Kaggle·Hugging Face 의 비공식 사본을 쓸 수 있으나 **라이선스를 직접 확인**할 것.

## 1. 클래스 정의 (제안, 사용자 확정 필요)
| 학습 클래스 | BDD100K 매핑 | 비고 |
|---|---|---|
| 신호등 red / yellow / green / off | `traffic light` 의 색 속성 (red, yellow, green, none→off) | HybridNets 는 `traffic_light_color: true` 로 지원 |
| 사람 | person + rider | 코드 수정 필요(두 클래스를 하나로 합침) |
| 자동차 | car + truck + bus | 이륜차·자전거·기차를 어디에 넣을지 **결정 필요** |
| **장애물** | **학습하지 않음 (2026-10-07 사용자 확정)** | 물체 종류는 중요하지 않고 **거리만 잴 수 있으면 된다.** 클래스 데이터가 필요 없다 |
| 차선 (분할) | BDD100K lane marking (126,013장, 마킹 604,379개) | 원거리 차선용 |
| 주행 영역 (분할) | BDD100K drivable | 필수는 아님. 학습 안정에 도움이 될 수 있어 선택 |
**장애물 거리 측정 방안 (구현 전, 미검증)**: 종류와 무관하게 앞에 있는 것의 거리를 재려면 검출 박스에 의존하지 않는 방법이 필요하다.
① 깊이 지도에서 주행 경로 영역(차선 사이 등)의 가장 가까운 거리를 쓰는 방식 — 칩의 `SpatialLocationCalculator` 에 관심 영역(ROI)을 주면 영역별 거리를 칩에서 얻는다(DepthAI 일반 기능, 이 프로젝트에서는 아직 안 써 봄).
② 사람·자동차 검출이 놓친 물체는 ①이 보완. 깊이는 스테레오라 가까운 거리에서 정확하고 멀수록 오차가 커진다(일반 특성, 이 카메라 실측 필요).
평가: 알려진 거리에 물체를 두고 측정 거리 오차와 "거리가 나온 비율(유효 깊이 비율)" 을 본다 (학습·정답 라벨 불필요).

"정지·돌발"은 클래스가 아니라 **움직임 상태**일 가능성이 커서(제 해석, 확인 필요) 검출 학습이 아니라 프레임 간 추적 후처리로 다룬다.

## 2. 평가 기준 (도구는 이미 있음, `accuracy/`)
| 항목 | 지표 | 목표 | 도구 |
|---|---|---|---|
| 신호등 색 | 위치+색이 맞은 재현율 (정밀도 같이) | ≥ 80% | `eval_core.py` (신호등 4색), `eval_accuracy.py` |
| 객체(사람·자동차) | 클래스별 재현율 @IoU 0.5 (정밀도·AP50 같이) | ≥ 80% | `eval_det.py` |
| **장애물 거리** | 거리 오차(알려진 거리 대비)·유효 깊이 비율 | 사용자 목표 없음(제안: 오차·유효 비율 보고) | 카메라 실측 |
| **차선** | **프레임 단위 검출 여부** (선이 있는 프레임에서 찾은 비율 = 검출률, 오경보율도 같이) — **사용자 확정(2026-10-07)** | 검출률 ≥ 80% | `eval_seg.presence_stats` |
차선을 검출 여부로 보면 공개 모델의 픽셀 IoU(26~34%)에 의존하지 않는다. 픽셀 정확도·IoU 는 참고로만 보고한다. 검출 여부는 "선이 있다고 라벨된 프레임"이 필요해서 BDD100K lane 라벨의 존재 여부로 만든다.

## 3. 학습 순서
| 단계 | 내용 | 모델 | 산출물 |
|---|---|---|---|
| A | 학습 없이 후보 블롭 속도 실측 | 5개 모두(사전 학습 가중치/구조) | `chip_bench.py` 결과 → 지연 100 ms 를 넘는 모델 제외 |
| B | 데이터 변환·확인 (BDD100K → 모델별 형식) | | 변환 스크립트, 샘플 시각화 |
| C | **검출 헤드만** 새 클래스로 학습 (인코더·분할 헤드 고정) | 1순위 하나 | 기준선 점수 |
| D | 신호등 보강: 우리 신호등 데이터 3,997장(세로형 위주)·국내 데이터·자체 촬영으로 이어서 학습 | | 신호등 80% 확인 |
| E | 입력 크기 비교(416 / 512×288 / 640×384): 인식률 vs 칩 지연 | | 해상도 결정 |
| F | 칩 변환 → 지연·fps·인식률 최종 측정(Raw 켬/끔) | | 판정 |

## 4. 모델별 시작 방법 (코드 확인에 근거, 실제 학습은 미검증)
- **A-YOLOM**: `ultralytics/datasets/bdd-multi.yaml` 에 `labels_list`(detection-object, seg-drivable-10, seg-lane-11), `nc_list: [1,1,1]`. 검출을 여러 클래스로 쓰려면 `nc_list` 의 첫 값, `names`, `map` 을 고치고 학습 호출에서 `single_cls=False`, `combine_class` 제거. 원본 학습 호출: `model.train(data=…bdd-multi.yaml, batch=12, epochs=300, imgsz=(640,640), device=[0,1,2], task='multi', classes=[2,3,4,9,10,11], combine_class=[2,3,4,9], single_cls=True)`. 가중치는 저장소 README 의 링크(n, s). **AGPL-3.0**.
- **HybridNets**: `projects/bdd100k.yml` 복사 → `obj_list` 에 클래스, `traffic_light_color: true`, `seg_list: ['road','lane', …]`(마스크 폴더를 `dataset.segroot` 에 같은 순서로), `python train.py -p <프로젝트> -c 3 -n 4 -b 8`. 입력 128 배수. ONNX 는 `export.py` + 빈 `Pad` 입력 제거(README 2절).
- **YOLOP**: 검출 `nc` 가 `lib/models/YOLOP.py` 에 1 로 고정돼 있어 다중 클래스는 코드 수정 필요. 분할은 `num_seg_class`. `TRAIN.DET_ONLY` 등으로 단계별 학습.
- YOLOPX: 코드 공개. YOLOPv2: 학습 코드 없음.

## 5. 위험
| 위험 | 대응 |
|---|---|
| 신호등이 작아 작은 입력에서 놓침 | 입력 512×288 이상, 작은 물체용 층 추가 검토 |
| 깊이 켬에서 SHAVE 가 줄어 지연 증가(추정 116 ms) | `chip_bench.py` 로 6 SHAVE 실측, 입력·모델 크기 조정 |
| BDD100K(미국)와 국내 도로 차이 | 국내 데이터·자체 촬영으로 미세조정 |
| 장애물은 클래스가 없어 사람·자동차 검출이 놓친 물체의 거리가 비어 있을 수 있음 | 깊이로 주행 경로 영역의 최근접 거리를 따로 재서 보완(구현·실측 필요) |
| 라벨이 없는 과제(우리 신호등 데이터에는 차선·객체 라벨 없음) | 한 단계에서 한 과제만 학습(단계별) 또는 손실에서 해당 과제 제외 |
| BDD100K 라이선스(비상업 연구 기본) | 제품화 계획이 있으면 확인 |
