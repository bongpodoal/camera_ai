# model_candidates — 전방 중앙(CAM01) 한 모델(차선 + 신호등 색 + 객체) 후보 5개 분석

작성: 2026-10-07 (맥에서 가능한 분석만, 학습·BDD100K 제외). 목표: 칩 지연 ≤ 100 ms, ≥ 5 fps, 인식률 80%.
후보(사용자 확정): ① A-YOLOM ② YOLOPX ③ HybridNets ④ YOLOP ⑤ YOLOPv2.

## 1. 구조 측정 (직접 측정: `measure_arch.py`, 가중치 없이 구조만)
GMACs = 곱셈-덧셈 1쌍을 1로 센 연산량. 속도는 구조가 정하므로 학습 전에 잴 수 있다.

| 모델 | 파라미터 | 320×320 | 512×288 | 640×384 | 검출 헤드 | 분할 헤드 |
|---|---|---|---|---|---|---|
| A-YOLOM(n) | 3.64 M | 2.32 | **3.35** | 5.58 | YOLOv8 방식(앵커 없음) | 주행 영역·차선 각 2채널 |
| A-YOLOM(s) | 13.61 M | 7.31 | 10.52 | 17.53 | 같음 | 같음 |
| HybridNets(d3) | 13.44 M | — | 4.57 (512×256) | 8.58 | 앵커 기반, 클래스 수 설정 | 클래스 여러 개(예: 4) |
| YOLOP | 7.94 M | 3.85 | 5.55 | 9.25 | 앵커 기반, **클래스 1개로 고정** | 주행 영역·차선 각 2채널 |
| YOLOPX | **32.98 M** | 18.51 | 26.66 | 44.43 | 앵커 없음, 클래스 1개 | 2채널 ×2 |
| YOLOPv2 | **38.95 M** | 15.08 | 21.71 | 36.19 | 255채널(앵커 3 × 85) | 2채널 + 1채널 |

- HybridNets 는 입력이 **128 의 배수**여야 한다(P7 이 stride 128). 16:9 에서는 640×384 만 가능하고 512×288 은 불가.
- 이 환경에서 A-YOLOM(n) 은 논문(4.43 M)보다 3.64 M 으로 나왔다(설정 파일 차이로 보이며 원인 미확인). s 는 13.61 M 으로 논문과 일치.

## 2. 칩(RVC2) 변환 가능성 (Luxonis 서버, OpenVINO 2022.1, 6 SHAVE = 깊이 켬 조건)
| 모델 | 결과 | 비고 |
|---|---|---|
| A-YOLOM(n) 512×288 | **성공**, 블롭 7.4 MB, 11초 | 출력: 검출 3스케일(65채널 = DFL 64 + 클래스 1) + 주행 영역 + 차선 |
| HybridNets(d3) 512×256 | **성공(ONNX 수정 후)**, 블롭 51 MB, 63초 | 그대로는 실패: ONNX `Pad` 노드 31개의 빈 선택 입력 때문에 Model Optimizer 가 `NullNode` 오류. `onnxsim` 후 빈 입력을 제거하면 통과 |
| YOLOP | Luxonis 가 이미 RVC2 용으로 변환(`luxonis/yolo-p`, 320×320) | 공식 15.61 inf/s |
| YOLOPX, YOLOPv2 | **시도하지 않음** | 연산량이 커서(26.7 / 21.7 GMACs @512×288) 100 ms 가 불가능하다고 판단 |

컴파일이 된 것은 "칩이 지원하는 층만 쓴다"는 뜻이지 속도·정확도 보장은 아니다. 블롭 속도는 `chip_bench.py` 로 카메라에서 잰다.

## 3. 칩 지연 추정 (`estimate_latency.py`, **추정**)
보정: 합성곱 중심 YOLO 계열 유효 처리량 약 58 GMACs/s(yolov6n·YOLOv8n·YOLO-P 세 곳이 58~60 으로 일치), YOLO11s 같은 새 블록은 약 38. 칩 지연 ≈ 추론 간격 × 1.5(실측). 깊이 켬은 SHAVE 8→6 으로 6/8 처리량(가정).

| 모델 | 입력 | GMACs | 추론(ms) 깊이 끔 | 칩 지연(ms) 깊이 끔 | 추론(ms) 깊이 켬 | 칩 지연(ms) 깊이 켬 | ≤100 ms (끔/켬) |
|---|---|---|---|---|---|---|---|
| A-YOLOM(n) | 512x288 | 3.35 | 58 | 87 | 77 | 116 | O / X |
| A-YOLOM(n) | 640x384 | 5.58 | 96 | 144 | 128 | 192 | X / X |
| A-YOLOM(s) | 512x288 | 10.52 | 181 | 272 | 242 | 363 | X / X |
| HybridNets(d3) | 512x256 | 4.57 | 120 | 180 | 160 | 241 | X / X |
| HybridNets(d3) | 640x384 | 8.58 | 226 | 339 | 301 | 452 | X / X |
| YOLOP | 320x320 | 3.85 | 66 | 100 | 89 | 133 | O / X |
| YOLOP | 512x288 | 5.55 | 96 | 144 | 128 | 191 | X / X |
| YOLOPX | 512x288 | 26.66 | 702 | 1052 | 935 | 1403 | X / X |
| YOLOPv2 | 512x288 | 21.71 | 571 | 857 | 762 | 1143 | X / X |

- **A-YOLOM(n) 512×288 만** 깊이 끔에서 100 ms 안에 들어온다(87 ms). 깊이 켬에서는 116 ms 로 넘는다(6 SHAVE 가정이 맞다면).
- YOLOP 는 320×320 에서만 경계(100 ms)이고, 신호등이 작은 입력에서 인식률이 안 나올 가능성이 크다(아래 4).
- HybridNets(d3) 는 EfficientNet 의 depthwise 연산이 이 칩에서 느릴 것이라는 가정으로 낮은 효율(38)을 썼다. 근거가 약하니 `chip_bench.py` 로 확인해야 한다.

## 4. 신호등은 입력 해상도가 인식률을 정한다 (YOLO11s PyTorch, 신호등 검증 567장)
| 입력(긴 변) | 실제 내용 크기 | 재현율 | 색 정확도 |
|---|---|---|---|
| 320 | 320×180 | 0.621 | 0.997 |
| 416 | 416×234 | 0.826 | 0.998 |
| **512** | **512×288 (16:9 전체)** | **0.911** | 0.999 |
| 640 | 640×360 | 0.954 | 0.999 |
| 960 | 960×540 | 0.968 | 0.999 |
→ 다중작업 모델의 입력은 **512×288 이상**이 안전하다(80% 목표에 여유). 320 급 입력은 신호등에서 미달 가능성이 크다. (960 으로 학습한 모델을 작게 돌린 값이라 작은 입력으로 학습하면 나아질 수 있다.)
